# bgm.res 本地收藏管理预览版

这是 JimHans/bgm.res 的独立管理入口，保留原版源码、资源与 GPL-3.0 许可证。新入口不加载原播放器、做种页面或旧数据库适配器；原版仍可从原 index.js 启动。当前实现是管理核心和新界面的第一阶段，并非原版全部功能的迁移。

## 使用

Windows 双击仓库根目录的 `启动收藏管理.cmd`（本机准备脚本生成）。重新准备启动环境可执行 `powershell -File manager/prepare-desktop.ps1 -RuntimeSource <官方便携版的win-unpacked目录> -NodeBinary <Node.js24的node.exe>`。脚本只复制运行时到本仓库 `.desktop`，不覆盖原安装。桌面外壳为 Electron，管理服务使用 Node.js 24 的内置 SQLite，无额外 npm 依赖。也可以用 Node.js 24 执行 `node manager/server.cjs`，在本机浏览器打开输出的网址；浏览器模式不提供打开目录。

在“导入收藏”填写 BangumiAutoRename 的 data 目录。导入只读 task 和 record，不读取密钥配置，也不写回原项目、操作原视频。记录必须包含已执行目标；仅存在任务但没有操作记录的目标不导入。按规范化目标路径去重，重复导入保留手动章节绑定。字幕不作为独立视频导入。

目录扫描是补充来源：选择每部作品一个子目录的媒体库根目录；名称和集号仅作线索，章节保持待确认。不自动挑选搜索结果、不把自然排序当作章节号、不自动删除缺失记录。扫描跳过符号链接与目录联接，避免循环。

资料更新按明确 Bangumi ID 请求完整章节目录（全类型、全分页），失败时保留旧资料。通过章节下拉框手动绑定。多个视频可绑定同一个章节，以表示多个版本。不同条目 ID 的更换会解除原绑定；标签和备注保留。尚未获取目录或存在未确认文件时不宣称缺集；页面只显示“无在线已绑定文件”的目录章节。

数据库默认在 `%LOCALAPPDATA%\bgm-res-manager\library.sqlite`，封面缓存在同目录 covers。Electron 配置另存在 `%APPDATA%\bgm-res-manager`，不接管原 bgm.res 的 MediaData.db。退出程序后可备份整个数据目录；迁移电脑时需重新确认媒体路径。排序只改变查询显示，不修改 ID。

## 当前边界

- 不播放、不下载、不搬移、不重命名、不删除媒体，不登录 Bangumi、不写入线上收藏或观看状态。
- 标签、备注保存在本地；资源大小为在线文件逻辑大小，硬链接不去重为物理占用。
- 卷根目录不可达显示磁盘离线；卷在线但文件不存在显示缺失；权限错误单独显示无法访问。网络目录状态受系统挂载行为影响。
- 尚无字幕轨道检测、视频编码探测、自动监视目录、旧 NeDB 导入、关联作品图、批量资料更新、全文搜索索引与超大库虚拟滚动。
- 导入记录时多条目任务的标题先沿用任务标题，更新对应 Bangumi 资料后纠正。
