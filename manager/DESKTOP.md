# 本地番剧管理界面

“确认归属作品”支持勾选多个候选或按 Bangumi ID 添加，顶部固定显示当前来源名称和完整路径。多归属会载入所选作品的章节目录，整包子目录共用一个待审核方案；不把文件默认归给第一个条目。方案页同样突出来源路径，支持筛选子目录后批量选择归属，再选择章节。未指定归属的文件无法通过检查或执行；需要跳过时可明确跳过。旧兼容目录须先迁移为条目目录后使用多归属。

发布组识别区分前置发布组标签和编码／分辨率标签，支持技术参数之后的末尾署名（如 `- mawen1250`）。目录没有有效发布组时再核对视频文件；多个文件给出冲突组名则留空。重新识别时丢弃历史上误填入发布组的技术参数，正常手动指定值继续优先使用。已完成输出的命名修正仍需生成并审核新方案。

桌面整理使用专用后台 `pythonw -m src.desktop_service`，直接运行 FastAPI／Uvicorn，不加载 NiceGUI 网页和页面组件。旧 NiceGUI 网页入口已移除。桌面通过鉴权接口登记自身进程；界面关闭后已排队、正在执行的工作继续，所有桌面进程退出且任务结束后后台自动退出。启动宽限期为三十秒，后台每秒检查一次进程与队列。

整理后台状态包含 PID、代码签名、数据目录和运行版本。桌面自动识别代码变化，在没有未取回结果、排队或执行任务时，通知旧后台退出，再启动新版；不停止其他项目的数据服务。数据目录使用进程锁，避免重复实例覆盖访问令牌。重启后任务列表与方案继续读取原有记录，本次没有迁移到 SQLite，内存任务状态的断电恢复仍是后续工作。

识别补充召回支持 Tenrai（MyAnimeList 兼容接口）：保留资源名的续作、季号和特别篇意图，清理明确的编码／分辨率标签。Bangumi 无精确匹配时，拉丁字母查询会用 Tenrai 返回的日文名补搜 Bangumi；每次最多核对三个外部候选，合并已召回的 Bangumi ID，不再把候选截成五个。Tenrai 对应关系按用户脚本的宽松评分核对：标题短语 Jaccard 最高六分，年月与集数加分；采用扩大搜索的 0.5 分惩罚，2.5 分起采用对应关系并补充别名，低于 2.5 的对应关系不进入候选与缓存；低于 7.5 时按原名补搜（每次最多三个）并保留更高分结果。7.5 只控制补搜，不作为自动确认门槛。原名不要求完全相等，自动确认继续检查查询标题、季号、类型与候选歧义。重复依据按来源、MAL ID 和标题合并，历史记录展示时同样过滤未通过阈值的关系并去重；跨库对应分不是最终搜索排序分。文字证据不足时使用本地 pykakasi 自动读音补充，仅供排序和人工选择，不额外调用联网转换接口。

完整标题／别名匹配且无同分歧义、季号与特别篇冲突时才自动确认；其余结果留在“确认作品”供选择。成功与失败任务都保存候选，桌面候选显示原名、日期及 Tenrai 核对来源，选择 BGM ID 后生成新方案再审核。已存在的历史任务须重新识别才会补充候选。

`rename/title_cache/` 缓存 Tenrai 查询七天、核对通过的 Bangumi↔MAL 别名对应关系三十天；过期自动重新查询，原名或日期改变则不沿用对应关系，不缓存网络失败。无需安装向量模型。`engine/.venv/Scripts/python.exe manager/evaluate-title-recall.py` 使用隔离临时目录复测已有的二十二个标题查询（需先有 `.desktop/vector-eval/report.json`），结果保存在 `.desktop/title-recall-report.json`，不写入正式任务与媒体。

推荐双击桌面上的 `bgm.res` 快捷方式，或在开始菜单搜索 `bgm.res`；也可运行仓库根目录的 `启动 bgm.res.vbs`（无控制台窗口）或 `启动 bgm.res.cmd`。默认界面为 `desktop.html`，沿用原来的 `bgm.res-linked` 媒体库及 BangumiAutoRename 输出记录。

- 媒体库：海报 / 列表、名称搜索（Ctrl K）、TV / 剧场版 / OVA / OAD / WEB 类型、年份及观看状态筛选，支持评分排序。
- 详情：正片章节为默认页；每集提供系统播放器播放、单集 Bangumi 评论链接、看过 / 撤销、看到这里。后者按章节顺序批量标记当前集及之前的正片，后续章节状态保持原样；选择章节可展开本地版本。
- 特典：SP、NCOP、NCED、CM 等文件独立管理；空文件与失效路径从有效列表排除，异常页保留记录，不删除磁盘文件。
- 关联：本地已有条目用绿色和“本地”标记区分，直接跳转本地详情。
- 统一入口：侧栏、偏好设置及托盘仅进入当前桌面功能，已移除原版工具窗口入口和旧版“添加作品”任务栏快捷任务。
- 刷新：重新导入重命名记录并检查磁盘文件状态。原本为空文件的异常项在删除后从列表移除，记住已处理路径，重启不再重新显示；文件恢复后重新纳入检查。首次发现丢失的正片仍保留异常提示。
- 异常记录可逐条清除、按番剧清除或全库清除，磁盘文件保持原样；清除后不会在下一次扫描中重复出现，文件恢复正常后重新纳入管理。
- 章节文件、特典及异常文件提供“删除文件”，由主进程核验已登记路径并显示文件路径确认框，确认后移入系统回收站，同时重建章节与版本索引；不提供永久删除或删除目录。

主进程提供异步 `library:read` / `library:edit` 接口；批量观看状态只写入一次。新界面使用一个内容滚动区，无背景模糊、固定比例定位或全屏弹层。海报使用独立的 480×720 范围缩略图缓存，原图保留；图片只在视口附近加载，远离视口后卸载。海报网格按固定行几何虚拟化，只挂载可视行及前后各一行；滚动事件按动画帧合并，离开媒体库时释放观察器和节点。章节名最多显示两行，展开文件面板后显示完整名称。详情请求按访问缓存。

验证：`node --test manager/virtual-poster-grid.test.cjs manager/cover-thumbnails.test.cjs manager/desktop-api.test.cjs manager/rename-binding.test.cjs manager/linked-fixes.test.cjs`

普通鼠标滚轮使用约 140 毫秒的缓出过渡，连续滚轮合并处理；触控板精细滚动和嵌套滚动区域保留原生行为。指针按下、键盘操作或页面切换会取消正在进行的滚动动画，并尊重系统的减少动态效果偏好。

章节卡片使用 88px 紧凑高度，常态显示集数、两行标题与观看状态。播放、鉴赏、评论、看过及看到这里在鼠标悬停或键盘聚焦卡片时显示，五个操作按三列两行排列，操作区限制在当前卡片内；展开的文件面板仍保留完整操作。

## 资源整理与统一文件存储

侧栏“资源整理”直接在当前主窗口显示任务、识别信息、文件方案、字幕导入和整理设置，使用与媒体库相同的样式和导航。不会新开 NiceGUI 窗口，也不嵌入旧网页。Python 引擎已并入本仓库 `engine/`，后续只更新 bgm.res，保留原项目的 GPL 许可与作者信息。默认使用 `engine/.venv/Scripts/python.exe`；环境变量仍可覆盖源码和解释器路径。首次接管只读取旧存储指针并绑定原数据目录，不复制媒体或改写历史记录。

新增来源或重新识别只生成待审核方案，不清理旧输出、不复制或移动视频。方案支持选择条目和章节、添加关联条目、调整季集号、版本、自定义文件名及跳过。必须重新检查后才能执行，修改决定后检查失效；执行时再次核验磁盘状态。已有兼容目录可预览条目目录迁移。字幕支持按集号预览、手动选择视频及调整后缀后导入。执行成功后自动刷新管理端。任务分页与搜索在当前记录快照上进行；后台工作不随页面切换或窗口关闭中止。

未统一数据的旧安装首次整合仍要求原服务关闭，将旧 `data` 校验复制至管理数据目录的 `rename` 子目录（默认 `%APPDATA%\bgm.res-linked\rename`），再写入引擎根目录 `.bgm-storage.json`。已经统一的数据直接沿用。原目录保留为迁移前备份；独立项目停止维护。迁移目录中的媒体别名保留为链接，不复制视频内容；因此旧目录及其媒体引用路径仍须保留。此前误复制的一份物语 06.5 视频已核验 SHA-256 后替换为原硬链接的符号链接，释放 2,890,223,455 字节。断开的旧源路径需要人工恢复，不能删除旧目录后假定所有历史恢复日志独立可用。

管理端 `MediaData.db` 继续用原 NeDB；整理端任务、操作记录、方案及日志继续用 JSON。没有迁移 SQLite。`BGM_RENAME_PROJECT` / `BGM_RENAME_PYTHON` 可指定后台源码和 Python 环境。服务默认仅监听本机 5999。桌面 API 使用运行时令牌（`rename/desktop-api.json`），写操作与旧整理入口共用执行锁；不要将此令牌或配置文件公开。默认关闭窗口不终止后台服务，以免打断正在执行的文件操作。

- `node --test manager/rename-integration.test.cjs manager/rename-binding.test.cjs manager/file-operations.test.cjs manager/desktop-api.test.cjs`
- Python 引擎：在仓库根目录运行 `engine/.venv/Scripts/python.exe manager/test-engine.py`，测试配置与输出均放入临时目录。

详情页显示 Bangumi 的具体开播日期（`AirDate`）；“开播时间（新→旧）”按年、月、日倒序，同日期按名称排序。年份筛选仍使用 `Year`。已有封面的条目补日期时优先使用本地元数据缓存，保留本地标题、封面及观看状态。只有年份的记录标注具体日期未知，不伪造月日；无日期记录排在最后。

## 媒体库字幕管理

番剧详情提供“导入字幕”按钮和“字幕”页签，不再要求前往整理任务页。按本剧已登记的视频和所属整理记录生成匹配预览，支持多版本选择、偏移、后缀和跳过。多条整理记录分组执行；部分成功后会提示已完成数量，已完成行取消勾选，避免直接重试重复导入。只支持已有整理记录的作品。

“检测全库字幕”在后台以最多两个文件并发读取轨道，详情页也可仅检测本剧。优先使用 `BGM_FFPROBE` 或 PATH 中的 ffprobe，未找到则使用捆绑 FFmpeg。每文件最多等待 15 秒；检测结果存于管理数据目录 `subtitle-index.json`，视频身份、大小或修改时间变化会重新探测。重新检测会重新检查外挂文件，导入字幕后自动更新本剧结果。

内封字幕读取字幕轨及其语言；外挂字幕匹配同目录以及 Subs/Subtitles 目录内的视频同名或点号后缀文件，优先匹配最长视频名，不用相似标题跨作品猜测。检测文件存在和字幕轨不保证字幕有效或包含中文。画面内嵌无法由轨道可靠判断，需手动标记；未检测到字幕显示待确认，离线及失败显示未知。手动确认随文件身份保存，替换视频后失效。

媒体库可筛选全剧有字幕、部分集有字幕、已确认无字幕、待确认、未检测/未知。按正片章节计数，同一集任一版本有字幕即算该集有字幕；逐文件结果在详情页查看，特典不计入“全剧”覆盖率。

验证：`node --test manager/subtitle-index.test.cjs manager/desktop-api.test.cjs manager/file-operations.test.cjs manager/virtual-poster-grid.test.cjs`。另外使用 FFmpeg 生成临时内封/无字幕视频，验证真实轨道探测和新增外挂后的缓存更新，不修改真实视频。

## Bangumi 特别章节卡片

详情页新增“特别章节”，读取当前条目的全类型、全分页章节目录，按特别篇/OVA、OP、ED、预告、MAD 及其他类型分组展示。OVA 是发行形式，卡片分组依照 Bangumi 的章节类型，不把普通本篇按标题擅自归为特别篇。只按章节 ID 关联本地版本：未绑定显示“未映射本地文件”，已绑定但登记为失效的文件显示“已映射 · 文件不可用”。不能由未映射直接推断未下载；未绑定的本地资源仍在“特典文件”。任一目录分页失败会提示加载失败，不将半份目录展示为完整结果。

验证：`node --test manager/episode-catalog.test.cjs manager/rename-binding.test.cjs manager/desktop-actions.test.cjs`。

特别章节和正片共用章节卡片、悬停操作及文件展开组件。支持播放、评论、看过/撤销和看到这里；无可用映射时播放禁用。“看到这里”仅作用于当前特别章节类型，不改变正片或其他分组。观看状态以 Bangumi 章节 ID 保存在 `SpecialEpisodeStates`，本地重新导入后仍保留。

自定义命名只需填写标题，方案检查会自动补上已识别字幕组及源视频扩展名，关联字幕/音轨随最终视频名同步调整。兼容填写完整名称：同字幕组（忽略大小写）及原扩展名不会重复添加；不支持通过命名改变视频格式。最终名称可在重新检查的目标预览中确认。

方案打开时自动生成最终映射预览并检查磁盘，无须先手动重新检查。问题行置顶，保留有效行的预览；按源路径和关联字幕/音轨归属问题，支持搜索和只看需核对。视频采用每页 40 条的紧凑源→目标行，编辑控件按展开加载；关联字幕/音轨映射单独折叠。修改决定后保留上次预览并标为待更新，执行禁用，更新检查后才恢复；执行前仍严格检查磁盘与决定。单次导入生成方案后自动打开审核页，多任务可返回待审核列表查看其余方案。

## 取消识别方案

重新识别前在 `rename/recognition_reviews` 保存原任务及原方案的元数据快照；取消时恢复原任务和原方案，不操作媒体，也不改写操作记录。连续重新识别保留最初快照。取消可从审核页或任务列表进入；执行成功后快照结束。操作记录变化、任务另外被编辑或方案被替换时拒绝覆盖。取消中断后可再次取消以继续恢复。

快照功能加入前的旧方案只能“放弃此方案”，保留现有文件和当前识别信息，不宣称恢复历史识别信息。该任务显示“已取消”，后续仍可重新识别。已执行的文件操作不通过此入口撤销。

媒体库排序选择以 `library-sort` 保存在桌面本地存储，切换页面、刷新及重启后恢复；排序下拉框与实际排序保持一致，无效存储值回退到名称排序。

外观：默认使用淡化背景图片，侧栏和滚动浮标启用毛玻璃。可在偏好设置的外观区域独立关闭，两项选择会在本机保存。背景固定，海报及章节列表不使用逐卡片模糊。

详情页背景使用当前作品的海报，静态模糊并加深色遮罩；无封面时回退默认背景。返回总览时恢复默认背景，仍受外观中的背景图片开关控制。

DeepSeek：在资源整理的整理设置中填写独立API Key，然后在Bangumi待审核方案中手动点击辅助映射。支持待确认文件或全部自动映射，保护手动编辑；方案显示置信度、依据及用量估算。默认关闭思考，本次最多100文件、6次请求，按当前高峰单价预留约¥0.77；查看最近AI调用记录可见失败及用量未知情况。未配置密钥不会调用，不自动执行文件整理。

正片章节与特别章节均按Bangumi完整目录展示。正片顶部汇总未映射集号和文件不可用数量；未播出章节独立标注，不计入缺集提醒。多版本中有一个可用即视为可用；保留未匹配目录的本地章节，不用连续本地索引推断实际集号。目录加载失败时保留本地卡片并提示无法核对，不据不完整目录报告缺集。

章节卡片显示播放时长：优先Bangumi的duration_seconds及可解析duration，缺少时后台读取当前本地播放版本。卡片以BGM/本地标明来源；未映射无文件且无BGM时长则不虚构数字。最多并发检测两个文件，结果缓存于duration-index.json；字幕轨道检测也保留时长供复用，文件签名变化会使缓存失效。

整理任务可通过“删除记录 / 关联文件”预览并确认删除，默认保留媒体输出；可选将独占登记输出移入Windows回收站。源路径、其他任务共用输出和目录保留；元数据先备份到rename/deleted_tasks。删除成功会同步更新媒体库绑定。

删除关联输出后，递归清理预览中列出的作品边界内的空目录，并汇报数量；有剩余内容、其他任务引用、来源或目录链接的部分会保留。仅删记录不清理目录。

正片合集：详情页的本地文件支持“设为合集”，选择同一条目的至少两个章节。合集显示在正片章节下方，以“作品名 [字幕组]”展示，并参与正片播放、观看进度和字幕检测。覆盖的章节计为已映射；分类和观看状态在刷新及重启后保留。资源整理方案也支持“合集（正篇）”及多选章节，默认输出文件名为“作品名 [字幕组]”加原扩展名。

在媒体库中设置合集后，点击“保存并重命名”会将视频及同目录关联字幕改为“作品名 [字幕组]”，同时更新整理记录与媒体库路径。已有合集可从文件操作的“合集设置 / 重命名”再次执行。目标文件已存在时中止；链接媒体会同步更新镜像及链接，保存失败时回退本次改名。

资源整理中切换为“合集（正篇）”默认选中当前作品的全部章节。章节使用复选框逐项调整，支持全选、清空和已选数量提示，无需 Ctrl 多选；已手动调整的选择会保留。

详情页的“打开文件夹”与文件“定位”会将对应资源管理器窗口切到前台；已最小化的窗口会恢复，已有最大化状态保持。

本地文件行的“打开原视频文件夹”按整理记录中的 source 打开整理前的来源目录，并将资源管理器置于前台。来源文件已移走但目录仍存在时仍可打开；无来源记录时按钮禁用，目录离线或不存在时显示提示。

本机已在 Windows 启动文件夹加入 `bgm.res.lnk`，登录后自动启动；删除启动文件夹内这条快捷方式即可停用，不影响桌面入口。所有入口使用同一媒体库数据目录，重复启动会聚焦已有窗口。

## 识别性能与诊断

识别先清理视频扩展名及 `[vN]` 版本标签，保留标题、年份与季号。候选详情最多三个并发请求，按原候选顺序评分；网络失败不再切换标题和年份反复搜索。交互识别每个请求最多尝试两次，整个识别共享 20 秒联网等待预算，缓存命中不受该预算阻止。

公开条目与完整章节按 10 分钟有效期缓存到 `rename/metadata_cache`，最多 256 项、16 MiB。过期章节不会在断网时降级使用；认证响应不写入磁盘缓存。空的关联条目列表也缓存。原生方案只获取一次完整章节，避免额外请求正片列表。

目录检查优先查当前层视频，不先遍历所有子目录；同一次识别中复用 `os.scandir` 生成的文件快照。单文件只枚举同级伴随文件。扫描缓存不会跨识别任务保存；审核检查和执行仍读取当时的磁盘状态。机械硬盘唤醒和首次目录读取的 I/O 延迟仍可能存在。

后台任务提供扫描、条目搜索、章节获取、文件匹配、方案检查的阶段进度及耗时，桌面整理页显示当前阶段。文件执行继续共用串行锁。

复测：`engine/.venv/Scripts/python.exe manager/profile-recognition.py --output .desktop/recognition-profile-optimized.json`。脚本在临时目录中运行真实预览，禁止写入源媒体与正式记录；对比自动搜索、指定 ID、内存及磁盘缓存，并输出请求与 cProfile 耗时。这里的冷缓存只指 HTTP 缓存和连接，未清空操作系统磁盘缓存。

## 字幕选择与性能

作品详情的字幕页支持单个或多个字幕文件、单个目录，也可直接粘贴字幕文件或目录路径。文件选择器按 ASS、SSA、SRT、VTT、SUB、IDX、SUP、SMI、SAMI、TTML 筛选；多文件预览只包含明确选择的文件，不扫描它们的同级目录。取消选择保留原方案，重新选择或修改偏移会使旧方案失效。

同一作品的多条整理记录使用一次批量预览；字幕来源只扫描一次，视频和原文件名各解析一次并建立集号索引。多版本或跨记录存在歧义时保留为待选择。执行仍检查原视频、目标冲突并保留日志、回滚和部分完成提示。

字幕检测在一次扫描中共享目录列表和外挂索引，下一次扫描重新读取目录。导入成功后只刷新受影响视频的外挂字幕，不再重新导入媒体库或重复整剧轨道检测；外挂刷新使用独立的 I/O 队列，不等待后台视频探测，并防止旧扫描结果覆盖新导入的字幕。未知轨道保持未探测状态，后续完整检测仍会读取轨道。

索引写入合并并发请求，全库检测按时间检查点保存及完成后保存，避免每 25 个视频序列化整个索引。文件复制和回滚日志的持久化步骤保留。

复测：`node manager/profile-subtitles.cjs` 对现有缓存视频做只读比较，不写入实际字幕索引或运行 ffprobe；`engine/.venv/Scripts/python.exe manager/profile-subtitle-import.py` 使用临时生成的 120 个视频、240 份字幕比较旧匹配循环和新索引，校验结果一致。结果位于 `.desktop/subtitle-scan-profile.json` 和 `.desktop/subtitle-import-profile.json`。磁盘与网络环境会影响实际端到端等待时间，基准未清空系统磁盘缓存。


## AI 方案辅助模型

待审核方案支持 GLM-5.3-Flash、GLM-5.3-FlashX、免费 GLM-4-Flash-250414 与 DeepSeek。整理设置可选择默认模型并分别保存智谱和 DeepSeek 密钥；密钥不返回界面、不写调用日志。调用只发送相对文件名与候选章节，不上传视频，不直接执行文件操作。GLM-5.3 使用低强度思考，免费 GLM-4-Flash 关闭思考。

赠送资源包模型与免费模型分别标注；赠送模型显示的是抵扣前目录价估算，不能当作实际扣费。`glm_gift_expires` 控制资源包到期检查，到期或未配置有效期则在请求前阻止赠送模型调用，用户可改选免费模型。该检查不读取账户实时余量，也不统计其他应用的消耗，实际额度与抵扣结果以平台为准。失败不会自动切换到另一付费平台。

等待识别期间只锁定当前方案的修改与执行，保留返回、筛选、展开与翻页；离开方案后完成的结果仅通知，不强制切换页面。


字幕页进入时只读取已有检测结果，不自动重新探测视频；使用“检测本剧字幕”主动更新。概览、外挂导入和视频版本检测结果分区展示；结果按状态筛选、搜索文件名或路径，轨道、人工确认与完整路径按需展开。导入匹配显示目标与待确认状态，提交前显示导入及跳过数量，无有效目标时禁用提交。来源或偏移变化后预览失效；部分导入成功后仅保留未完成行，避免重复处理。


方案页提供“确认映射”、勾选后的“确认选中映射”，以及“确认筛选映射（数量）”。只确认已有合法归属与章节、合集或附加资源分类，未匹配及跳过行保持原样；筛选确认作用于当前筛选结果的所有分页。确认通过原有检查接口保存人工确认及当前映射指纹，保留 AI 依据，不重选章节、不执行文件操作；文件冲突及缺失仍保留并阻止执行。归属、章节、命名或版本变化后，原确认指纹失效，需要重新确认。文件清单直接显示作品与章节，支持按检查问题、映射待确认、已人工确认与跳过状态筛选。


## 应用皮肤与海报大小

媒体库工具栏提供 120–280px 的海报大小滑块（10px 步进），偏好设置中也可调整。该值控制海报的最小宽度，实际宽度随窗口及列数填满网格；列表视图不受影响。拖动时刷新虚拟网格并尽量保留当前作品所在位置，不重新读取媒体库。海报大小与皮肤分别保存在本机 localStorage，刷新及重新启动后继续使用。

默认皮肤为参照 Codex 的中性石墨深色；“偏好设置 → 应用皮肤”可即时切换 Codex 浅色，也保留 Tokyo Night、Catppuccin Mocha、Rosé Pine 与 Catppuccin Latte 作为其他配色。皮肤统一覆盖导航、输入框、按钮、整理审核、字幕页及状态色；背景图和毛玻璃默认关闭，已有显式选择仍保留。原生标题栏覆盖颜色随皮肤更新。

配色参考 [Tokyo Night](https://github.com/tokyo-night/tokyo-night-vscode-theme)、[Catppuccin 官方色板](https://catppuccin.com/palette/) 与 [Rosé Pine 官方色板](https://rosepinetheme.com/palette/)，界面语义色和浅色强调色为可读性做了适配。


2026-11-05：整体界面改为参照 Codex 的中性工作区。首次加载新版将原皮肤选择迁移为 `codex-dark`，保留已保存的海报大小；之后的皮肤选择照常保存，也可重新选择旧色板。新增 `codex-light`。导航收为图标栏，工具按钮提供悬浮及键盘聚焦提示；Escape、滚动及离开操作会关闭提示。整理任务使用列表，设置按分区展示。页面标题、主要动作、冲突与执行信息继续显示文字。

详情标签、媒体库筛选、整理审核行编辑与字幕导入使用局部更新；未变化的卡片和输入控件继续保留。后台媒体库通知合并处理，不重建正在编辑的详情、字幕导入或设置页面。详情摘要即时更新，当前子面板在切换标签或主动刷新时读取最新数据。隔离 Electron 交互回归入口为 `manager/partial-render.electron.cjs`，仅使用内置测试数据，结果和截图输出到 `.desktop/partial-render-qa/`。

## 字幕版本与下载收件箱

作品的字幕页按语言后缀／字幕组汇总外挂版本，默认收起导入和逐视频检测明细。版本行提供文件明细、整套替换和移除图标；内封字幕只读。导入预览支持批量语言与字幕组后缀，默认保留识别出的语言；正常匹配折叠，冲突会阻止执行。替换仅处理已匹配视频，未匹配的旧字幕保留；原目录和媒体库同步更新，旧文件从原路径移入系统回收站。

字幕下载记录持久保存在收件箱。部分导入保留整个包，继续导入默认只选剩余文件；全部导入或明确“放弃剩余并清理”后清理原包、解压文件和其他附件。手动选择的外部字幕原件不清理。整批导入失败时恢复本批文件和记录；中断操作可在字幕页恢复。通过持久操作回执核对应用关闭期间完成的导入，避免重新导入已完成内容。

验证：`node --test manager/subtitle-panel.test.cjs manager/subtitle-inbox.test.cjs manager/subtitle-sources.test.cjs`；在 engine 下运行 `.venv/Scripts/python.exe -m unittest discover -s tests -p test_subtitle_manage.py`。`manager/subtitle-versions-ui.electron.cjs` 使用隔离数据检查深浅色、宽窄布局和版本操作，不修改用户媒体。
